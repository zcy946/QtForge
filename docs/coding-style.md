# C++ 与 Qt 代码风格规范

本文档是 QtTileCanvas 的项目级 C++ 与 Qt 代码风格规范，约定命名、代码组织、注释及 Qt 开发惯例，
便于在多人协作或 AI 辅助编码时保持一致。新增代码和被修改的代码必须遵循本文档；未触及的历史代码
不要求一次性整改。本文档未规定的细节沿用当前模块的既有风格。模块如需例外，必须显式记录例外及其
适用范围。

---

## 1. 规范层级

- [`.editorconfig`](../.editorconfig) 是字符编码、行尾和通用文本格式的唯一权威。
- [`.clang-format`](../.clang-format) 是 C/C++ 机械排版格式的唯一权威。
- 本文档规定命名、代码组织、注释以及无法由格式化工具完整表达的约定。
- 本文档对机械格式的描述仅用于帮助理解；如与配置文件冲突，以对应配置文件为准。

配置要点：文本使用 UTF-8 和 LF 行尾；C/C++ 使用 4 个空格缩进、不使用 Tab、单行最多 120 列、
Allman 大括号风格，指针和引用符号靠近变量名。完整规则以对应配置文件为准。

## 2. 命名

### 2.1 通用 C++

- **类型（类、结构体、枚举）**：`PascalCase`。QtTileCanvas 应用内部类型不强制添加全局前缀。
  `EyLogger` 等独立可复用库保留其公共 API 前缀。类型前缀必须由模块公共 API 统一
  决定，不得由开发者逐个类型自行选择。
- **函数、方法**：`camelCase`；公开 API 建议动词开头、语义完整。
- **成员变量**：前缀 **`m_`** + `camelCase`（如 `m_data`、`m_maxLineCount`）。
- **界面对象成员**：必须在 `m_` 后保留完整控件类型前缀，再写语义，例如
  `m_pushButtonAddTrace`、`m_plainTextEditLogInput`、`m_treeViewDevices`。对应普通连接回调沿用同一
  对象名，例如 `onPushButtonAddTraceClicked()`。此规则不扩展到局部变量。
- **局部变量、参数**：`camelCase`，按变量职责命名；短生命周期可用简短名称，但避免含糊的 `tmp`、
  `ret`。不使用 `v`、`h`、`p`、`str` 等类型缩写前缀；类型或方向确实构成语义时使用完整单词。
- **宏、全文件常量**：习惯上全大写或项目统一前缀；与所依赖库（Qt、spdlog 等）的惯例冲突时，**以库为准**。
- **命名空间、文件名**：与模块、主类名一致；`.cpp` 内可用**匿名命名空间**封装翻译单元私有实现。

### 2.2 Qt 信号与槽（在使用 Qt 时）

- **`Q_OBJECT`**：`QObject` 派生类声明信号、元对象槽、属性，或承载需要通过 `tr()` 翻译的界面
  文本时，必须添加 `Q_OBJECT`；完全不使用这些元对象能力的类不添加。
- **区块位置**：`Q_SIGNALS:` 以及各可见性的 `Q_SLOTS:` 区块放在普通 `public:` 区块之前。
- **信号声明**：使用 **`Q_SIGNALS:`**；发射信号时使用 **`Q_EMIT`**。
- **信号名**：前缀 **`sig_`** + 语义，例如 `sig_configLoaded`、`sig_filterRuleChanged`。
- `connect` 必须使用类型安全的函数指针或 lambda 语法，禁止使用 `SIGNAL()` / `SLOT()` 字符串宏。
  优先使用可命名的独立成员函数或自由函数；lambda 仅用于很短且一次性的局部适配。
- 禁止使用 `connectSlotsByName()` 隐式自动连接。所有信号连接必须在 `initConnections()` 中显式
  书写，使控件或方法重命名后能够在编译期暴露问题。
- 使用 lambda 连接时必须传入 context 对象，使连接在 context 销毁时自动断开，并使用显式捕获，
  不得使用无约束的 `[&]` 或 `[=]`。
- 使用函数指针形式的 `connect` 时，接收函数是普通成员函数，不必声明为 Qt 槽。此类私有回调使用
  **`on<Object><Signal>`** 命名，例如 `onPushButtonAddTraceClicked`。
- 只有需要 Qt 元对象能力时，才在 **`public Q_SLOTS:`** 或 **`private Q_SLOTS:`** 中声明槽，例如
  需要字符串调用或向 QML 暴露的函数。
- **元对象槽名**：前缀 **`slot_`**；若槽对应某一对象上的某一信号，可采用
  **`slot_<对象语义>_<信号语义>`**，例如 `slot_searchEdit_textChanged`。
- 通过字符串调用槽（如 **`QMetaObject::invokeMethod`**）时，名字必须与声明完全一致。

测试模块例外：QtTest 按固定名称识别 `initTestCase()`、`cleanupTestCase()`、`init()` 和 `cleanup()`
生命周期钩子，这些函数保留框架规定的名称；普通测试槽仍使用 `slot_` 前缀。

## 3. 头文件与 include

普通 C++/Qt 声明使用 `.h`，并将实现放在对应 `.cpp` 中。Header-only、模板或其他必须在头文件中提供
主要实现的代码使用 `.hpp`。文件名使用 `PascalCase`，并与其中的主要类型保持一致。

### 3.1 头文件保护

头文件必须使用传统 include guard，不使用 `#pragma once`。默认将文件名及扩展名转为全大写下划线
形式，例如 `MainWindow.h` 使用 `MAINWINDOW_H`，`EyLogger.hpp` 使用 `EYLOGGER_HPP`。
Guard 宏必须在仓库内唯一；发生重名时，添加有意义的模块前缀或后缀消歧。文件移动但未改名时，
不修改 guard。

### 3.2 依赖与分组

- 头文件必须直接包含自身声明所需的依赖，不得依赖其他头文件的间接包含。
- 仅以指针或引用使用的类优先前置声明；需要完整类型时直接包含对应头文件。
- `.cpp` 的对应头文件独占第一组，然后依次排列当前项目头文件、Qt 与其他第三方库头文件、C++ 标准库
  头文件。
- 各组之间保留一个空行；组内顺序由 `.clang-format` 管理。

```cpp
#include "MainWindow.h"

#include "EyLogger.hpp"

#include <QHBoxLayout>
#include <QPushButton>

#include <memory>
#include <string>
```

## 4. 注释与文档

注释和 Doxygen 默认使用简体中文。类型名、API 名、协议名以及难以准确翻译的技术术语保留英文。
不得仅为统一语言而翻译无关的既有英文注释；实际修改相关内容时再按本规范调整。

普通注释解释代码本身无法直接表达的原因、约束和非显然行为，不得复述代码正在执行的步骤。公开 API
的 Doxygen 描述调用契约、参数语义、返回值、前置条件及其他调用方必须了解的信息。

### 4.1 Doxygen（公开 API、头文件）

对需要被阅读或生成的声明，使用块注释，常用标签：

| 标签 | 用途 |
|------|------|
| `@brief` | 一句话说明职责或效果 |
| `@param` | 各参数含义 |
| `@return` | 返回值；无返回值可省略 |
| `@note` | 前置条件、线程、与相关 API 的关系、注意事项 |

代码中的类型、函数名在注释里可用反引号标出，例如 `` `MyClass::init` ``、`` `Qt::UserRole` ``，便于阅读。

**示例：**

```cpp
/**
 * @brief 使用默认构建配置完成一次性初始化。
 * @return `true` 表示关键资源已就绪；`false` 表示降级路径或仅部分功能可用。
 * @note 重复调用行为由实现定义；若提供重载，在注释中说明彼此关系。
 */
static bool init();
```

不强制文件头注释。不要添加 `@author`、`@date`、`@version` 或逐文件版权信息；作者与变更历史由 Git
记录，版本由构建系统管理，版权与许可由仓库根目录的许可证统一声明。只有当文件职责、约束或使用方式
无法从声明本身清楚看出时，才添加简短的文件级 Doxygen 说明。

### 4.2 长实现文件中的分段注释（与 Doxygen 互补）

在**较长的 `.cpp`** 中，可用**非 Doxygen** 的等号/横线注释划分逻辑块，便于扫读；**不替代**对外 API 上的 Doxygen。

- **一级分段**（大块）：

```cpp
/* ==================== 分段名称 ==================== */
```

- **二级分段**（子块）：

```cpp
/* ------------------ 子项名称 ------------------ */
```

将 `分段名称`、`子项名称` 换成真实语义；同一文件内建议 **`===` 表大块、`---` 表其下子块**，层级清晰即可。

## 5. 实现习惯

- **修改已有文件时**：新增或修改的代码遵循本文档；本文档未规定的细节沿用该文件现有写法，避免同文件内混用多种成员前缀或注释格式。
- **类布局**：`Q_SIGNALS:` 和各可见性的 `Q_SLOTS:` 区块位于普通访问区块之前。普通访问区块按
  `public:`、`protected:`、`private:` 排列，空区块省略。每个区块内依次放置嵌套类型与常量、
  构造/析构函数、普通函数、数据成员；同类成员按职责和使用顺序排列，不按字母排序。
- **成员指针初始化**：成员指针必须在声明处初始化为 `nullptr`，除非已经在构造函数初始化列表中初始化。
  即使初始化辅助函数稍后一定会为其赋值，也不得让成员指针以未初始化状态进入构造函数体。
- **额外作用域**：不得使用仅用于视觉分组的额外大括号。使用空行、清晰的变量名或辅助函数表达代码
  结构；只有需要控制局部对象生命周期或解决名称冲突时，才创建额外作用域。
- **日志语言**：开发与运行日志默认使用英文，内容描述便于检索和排障的事实，不使用面向用户的翻译
  文案。用户可见文本遵循界面与本地化规则，不受日志语言约束。
- **Qt 字符串**：用户可见文本使用 `tr("...")`，为本地化保留入口。不需要翻译的 `QString` 常量
  使用 `QStringLiteral("...")`。日志库、标准库或其他明确接收窄字符串的 API 使用普通字符串字面量。
- **`auto`**：只有显式类型无法书写或明显冗长时才使用 `auto`，例如 lambda、迭代器或复杂模板类型。
  不得仅因为右侧表达式能够推断类型就省略普通类型；使用 `auto` 时仍须显式保留 `const`、指针和引用
  语义。
- **局部不可变性**：局部变量初始化后不再重新赋值时，必须声明为 `const`；循环计数器、累加器和
  状态变量等确实需要变化的变量除外。函数值参数不在头文件声明中添加不影响接口契约的顶层 `const`。
- **提前返回**：前置条件不满足、输入无效或无需继续处理时，优先使用 guard clause 提前返回以减少
  嵌套；不得为了追求 early return 而拆散必须集中维护的不变量或清理流程。
- **所有权**：`QObject` 派生对象优先使用 Qt parent-child 所有权，并尽量在创建时传入 parent。由
  parent 管理生命周期的对象可以保存为普通指针，不得手动 `delete`；对象可能在持有者之前被外部删除
  时使用 `QPointer`。不属于 Qt parent-child 体系的独占资源使用 `std::unique_ptr`，不得使用拥有
  所有权的裸指针。
- **继承**：不打算作为基类使用的具体类必须声明为 `final`。只有明确设计为扩展点并定义了继承契约的
  类才允许继续派生。所有虚函数重写必须使用 `override`。
- **析构函数**：不需要自定义清理时，不声明析构函数。确实需要覆盖基类虚析构函数时，使用
  `~Type() override`，不重复写 `virtual`。需要显式默认实现时，优先在首次声明处使用
  `~Type() override = default;`；只有 PIMPL、ABI 或不完整类型等技术约束要求时，才将默认实现放到
  `.cpp`。
- **Qt 界面初始化**：根据职责按需定义 `initItems()`、`initLayout()`、`initConnections()` 和
  `initWidget()`，不得为不存在的阶段创建空函数，也不使用 `setupUi()` 包装这些调用。构造函数直接
  调用实际存在的初始化函数，并保持上述相对顺序：
  - `initItems()` 创建界面对象并设置对象自身的初始属性。
  - `initLayout()` 组织布局。
  - `initConnections()` 建立信号连接。
  - `initWidget()` 在前述步骤完成后同步界面的初始整体状态。
